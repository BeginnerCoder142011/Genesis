Getting started

What you need before the button appears

GENESIS is a Geode mod, so Geode has to be installed and working first. The Generate button only exists inside the Level Editor — there is nothing to click in the main menu.

RequirementSupportedNotes
Geometry Dash2.2081Stable target. 2.2091 needs the Geode 6 beta line.
Geodev5.0.0+Tested against v5.11.2, the current stable release for 2.2081.
GENESISv1.4.2All platforms except iOS (experimental).
SongRecommendedAn official track or anything in your saved music library — this is what the level syncs to.

Install

  1. Download the build for your platform from the download page.
  2. In game, open the Geode menu → Install from file and pick the .geode you downloaded.
  3. Or drop the file into your mods folder (paths below) and restart the game.
  4. Open Create Level → the editor. GENESIS adds a Generate button to the toolbar.
Windows C:\Program Files (x86)\Steam\steamapps\common\Geometry Dash\geode\mods
macOS ~/Library/Application Support/Steam/steamapps/common/Geometry Dash/Geometry Dash.app/Contents/geode/mods
Android /storage/emulated/0/Android/media/com.geode.launcher/game/geode/mods
iOS Files › On My iPhone › Geode › game › geode › mods
The button lives in the editor's top toolbar area, next to the other editor tools. If you are on a narrow phone screen it collapses into the toolbar row — see troubleshooting.

Your first generation

  1. Type a prompt like easy cube intro, 20 seconds, no orbs.
  2. Set Version to the object set you want, and Difficulty to Easy.
  3. Pick a song from your library so the beat grid is real, not assumed.
  4. Press Generate. The level is written from your cursor forward.
  5. Playtest. Not right? Press Re-roll — same settings, new seed. Or Ctrl+Z and refine the prompt.
Prompt guide

How to write a prompt GENESIS understands

The prompt is a level brief, not a command list. GENESIS reads it to decide what kind of gameplay to build, in which part of the song. It does not read it as a sequence of object placements — you are describing intent, and the generator handles the objects.

The five slots

A strong prompt fills most of these. Any slot you leave out is filled by the panel settings, so the prompt and the panel should not disagree.

SlotExamplesEffect
1. Gamemodecube · ship · ball · UFO · wave · robot · spider · swing · mixedPicks the movement model and the obstacle vocabulary.
2. Difficultyeasy · normal · hard · insane · extremeSets gap sizes, timing windows and gadget density.
3. Placement in the songintro · build · drop · breakdown · outro · "after 0:40"Decides where it writes and what the structure looks like.
4. Length"15 seconds" · "two drops" · "8 sections"How far forward the pass commits objects.
5. Gadget policy"no orbs" · "pads only" · "one dash orb at the end"Constrains orbs, pads, portals and speed changes.

Rules that actually change the output

  1. Name the gamemode. "Hard" alone gives you cube. "Hard wave" gives you a wave corridor.
  2. Say where in the song. The same prompt at the intro and at the drop produce different density — the drop is always busier.
  3. Give a duration. Without one, the pass runs to the end of the section it detected, which can be much longer than you wanted.
  4. Describe shape, not objects. "short hops with pads" works. "a spike at x=120 then an orb at x=340" is ignored — object coordinates are not a prompt.
  5. One idea per prompt. A prompt that asks for cube → ship → spider → wave in one sentence gets a muddled blend. Generate them one at a time.
  6. Keep the prompt consistent with the panel. If the panel says 1.9, don't ask for a swing portal — the version filter drops objects that didn't exist yet, and you'll get a simpler level than you described.
  7. Iterate with the seed, not the wording. If the structure is right but the patterns are dull, press Re-roll instead of rewriting the prompt.
  8. Decorate as a second pass. Build the layout first, then run a decorated pass over it. Asking for "beautiful decorated extreme" in one go usually produces a worse layout.

Words that do nothing

good, fun, cool, epic, feature-worthy — these carry no parameters. They are not harmful, they just don't move the output. Replace them with a difficulty, a duration or a gadget rule.

Bad vs. good

✕ vague
make a good level
✓ specific
normal-difficulty cube section for the drop, 20 seconds, pads allowed, no orbs
✕ object dictation
put a spike at x=120, a yellow orb at x=340, then a 2x speed portal at x=520
✓ shape
hard cube timing section, single jumps followed by a short orb chain, one speed change near the end, 15 seconds

Panel settings the prompt can't override

SettingValuesBehaviour
SourcePrompt · Song · Both"Song" ignores the prompt text and follows song structure only.
Version1.0 – 2.2Hard filter on the object pool. Always wins over prompt wording.
GadgetsOrbs · Pads · Portals · Speed · TeleportDisabling a class removes it even if the prompt asks for it.
ModeLayout · Full decoratedLayout writes gameplay only; decorated adds design on top.
DifficultyEasy → ExtremeBaseline; a difficulty word in the prompt refines it within one tier.
SeedintegerSame seed + same settings + same song = same level.
Worked examples

Prompts you can paste, per difficulty and version

Each example lists the exact prompt, the panel settings to pair with it, and what the generator actually commits. Copy the prompt, set the settings, re-roll until you like the seed.

Classic cube intro

Easy1.9
prompt
easy cube section for the intro of the song, 20 seconds, no orbs, single jumps and short gaps only
VERSION 1.9MODE LayoutDIFF Easy ORBS offPADS onPORTALS off

What you get: roughly 90 blocks of level at a steady 1× speed — flat runs, single spikes, low blocks you hop onto, and gaps wide enough to land and re-jump without practice. No air control, no orbs to time.

Why it works: it names the section (intro), fixes a duration, and removes the gadget class that would make Easy harder than it should be.

Cube into a short ship corridor

Normal2.0
prompt
normal-difficulty build-up, 8 seconds of cube into a 6-second ship corridor, then back to cube, 2.0 object set, orbs and pads on
VERSION 2.0MODE LayoutDIFF Normal ORBS onPORTALS on

What you get: a cube run, a ship portal, a corridor sized for a normal player (roughly three grid units of clearance at the tightest point), an exit portal back to cube, and a landing stretch wide enough that you don't die on transition.

Why it works: two gamemodes, both named with their own durations, plus an explicit object set. Anything more than two modes in one prompt tends to blend.

Spider platform hops

Hard2.1
prompt
hard 2.1 spider section at the drop, short teleport hops across floating platforms, one dash orb near the end, 15 seconds, no portals
VERSION 2.1MODE LayoutDIFF Hard ORBS onPORTALS offTELEPORT off

What you get: a drop-density section with the spider entered by portal from your cursor, platforms spaced so each hop is one input, and a single dash orb placed on the longest gap.

Why it works: it asks for one dash orb rather than "lots of orbs", and switches off the portal class so the section doesn't get chopped up by unrequested gamemode changes.

Wave at the drop, tight but constant

Insane2.2
prompt
insane 2.2 wave at the drop, tight corridor but constant height changes, 12 seconds, no portals, no orbs, layout mode, seed 4821
VERSION 2.2MODE LayoutDIFF Insane SEED 4821GADGETS none

What you get: a wave corridor that shifts vertically through the section instead of holding one line — the "constant height changes" phrase is what produces the variation.

Why it works: it pins the seed, so you can re-run the exact same level after tweaking one word and see precisely what that word changed. This is the fastest way to learn the prompt vocabulary.

Straight fly into 2× cube timings

Extreme2.2
prompt
extreme 2.2 mixed section: 4 seconds of straight fly, then cube timings on 2x speed, 10 seconds total, decoration off
VERSION 2.2MODE LayoutDIFF Extreme SPEED onPORTALS on

What you get: a wide-open straight-fly window, then a speed portal to 2× and a cube sequence of single-frame-readable timings. The playability guard will re-roll anything it can prove is impossible, so expect the seed to shift a little from the first draft.

Why it works: straight fly is a shape, not a gadget — naming it explicitly is the only way to guarantee the corridor stays open with no orbs in it.

Follow the song, don't over-specify

Songany
prompt
follow the song structure, hard difficulty, orbs and pads on, layout only
SOURCE Song librarySONG Jumper · 180 BPM DIFF HardMODE Layout

What you get: sections sized to the actual track — a sparse intro, a busier build, a dense drop — with every obstacle landing on the beat grid rather than on a fixed interval.

Why it works: with song sync on, the prompt's job is only difficulty and gadget policy. Asking for a specific length here fights the song; leave duration out and let the structure be detected.

Decoration-only pass over a finished layout

Deco2.2
prompt
decorate the existing layout only, no gameplay changes, neon purple and cyan palette, pulses on every beat, ground and background styling
VERSION 2.2MODE Full decoratedDIFF keep current

What you get: block design on the geometry that's already there, ground and background styling, pulse triggers on the beat, and camera/move work where the section is empty enough to support it. No obstacle is added or moved.

Why it works: "no gameplay changes" is the phrase that keeps the pass decorative. Palette names are read as colour intent, not exact hex values.

Object versions

What each version selector actually changes

The version selector is a hard filter on the object pool. GENESIS will only ever place objects, gamemodes and triggers that existed in the update you pick — so a 1.9 level never contains a swing portal, and a 1.7 level never contains spider pads.

VersionGamemodes availableWhat the generator adds
1.0Cube, shipClassic geometry only: spikes, blocks, pads, gravity and speed portals. No orbs, no colour channels, no triggers beyond the basics.
1.2Cube, ship, ballBall sections and gravity-flip gameplay become available.
1.9+ waveWave corridors, colour channels for simple decoration, custom-music-era level pacing.
2.0+ robotRobot jump arcs, user coins, move triggers and the first 2.x decoration vocabulary.
2.1+ spiderSpider teleport hops, dash orbs, red jump pads, more ring and pad variants.
2.2+ swing, jetpackSwing and jetpack gameplay, camera controls, post-processing, platformer-aware geometry, the full decoration set.
Mismatch is silent. If your prompt asks for something the selected version doesn't have, GENESIS drops it rather than erroring. A "swing part" on 1.9 becomes a cube part with no warning — always check the version chip before blaming the prompt.

Choosing a version for a real level

  • Authentic classic levels: pick 1.0–1.8 and keep decoration off. The restriction is the point.
  • Modern gameplay with a 2.1 look: 2.1 is the sweet spot — spider, dash orbs and the first proper decoration tools.
  • Full decoration, camera work, platformer ideas: 2.2 only. Everything below it lacks the triggers.
  • Matching an update's contest: select the exact version the contest targets, then leave it alone while you iterate.
Troubleshooting

When the panel misbehaves

Work down this list in order — the first four cover almost every report.

There is no Generate button in the editor

In order of likelihood:

  • The mod is installed but not enabled. Open the Geode menu → Installed → check GENESIS is on and not showing a version warning.
  • You are on GD 2.2091 with stable Geode (v5.x). Stable Geode only supports 2.2081; GENESIS targets 2.2081. Either downgrade GD or use the Geode 6 beta line with the matching GENESIS beta build.
  • The mod failed to load at startup. Check Geode.log (see below) for a line mentioning GENESIS.
  • You're looking in the main menu. The button is editor-only.
Geode shows the mod as unsupported / won't install

Geode refuses mods whose gd target doesn't match your game build. GENESIS declares 2.2081 for win, mac, android and ios. If your game is on a different build, the mod isn't installable until a build for that version exists.

On Android, an ABI mismatch looks similar: a 64-bit package on a 32-bit-only device (or the reverse) fails to load. Use the ABI toggle on the download page to get the right file.

Game crashes on launch, or Geode itself is broken

Every Geometry Dash update breaks Geode until it's updated. If the game crashes before the menu, start in Safe Mode, which loads no mods at all:

  • Windows / macOS: hold Shift while launching and keep holding until the game has loaded.
  • Android: press and hold the Launch button in the Geode app.

If it boots in Safe Mode, the culprit is a mod — enable them in halves to find it. If it crashes even in Safe Mode, the Geode installation is broken and needs reinstalling for your exact GD version.

The panel opens but Generate does nothing
  • No song in the level. Song sync needs a track — pick one from your saved library, or use Prompt-only mode. An empty song slot with "Song" as the source produces nothing.
  • Object limit. Levels have a hard object cap; if the level is nearly full, the pass can't commit. Check the object counter in the editor.
  • Cursor at a weird position. Generation writes from the cursor forward; if the cursor is far past your content, the level grows off-screen. Scroll to where you want it.
  • Prompt conflicts with the panel. A prompt that only asks for objects the selected version lacks (e.g. swing on 1.9) can resolve to nothing. Switch the version up or change the prompt.
Everything vanished after I pressed undo

That's by design. Each generation pass commits as a single undo entry, so one Ctrl+Z removes the whole attempt rather than 900 individual objects. If you wanted to keep part of it, redo, then delete the objects you don't want by hand.

Sync is off — obstacles don't line up with the beat
  • The song's BPM in the panel is wrong. Set it manually to the track's real BPM; GENESIS uses that value for the grid.
  • The track has a lead-in. Use the offset field to shift the grid so the first beat lands at 0:00.
  • The song was replaced after generation. Regenerate — existing objects keep the old grid.
  • Custom Newgrounds songs that failed to download fall back to a default tempo. Re-download the song from the level's song slot.
Decoration pass produces gaps or missing visuals
  • Decorated mode uses more object slots than layout mode. On a nearly-full level it will skip decoration rather than overwrite gameplay.
  • On iOS the decoration pass is the least-tested part of the mod — see the experimental note on the download page.
  • Camera and post-processing triggers need 2.2. Select 2.2 and re-run the pass.
iOS: the mod doesn't show up after installing
  • Keep the downloaded filename exactly as is. Renamed .geode files are not loaded on iOS.
  • Install by sharing the file from Files to Geode, or place it in On My iPhone › Geode › game › geode › mods.
  • Geode on iOS is experimental — make sure your loader is the one that matches your game build.
Where are the logs?

Everything useful for a bug report lives in the geode folder next to your mods:

  • geode/logs/Geode.log — the main log, including mod load errors.
  • geode/crashlogs/ — one file per crash, with the stack trace.

Attach both to an issue. A report with the log is usually fixed in a day; a report without one usually isn't.

The panel is cut off on my phone

The panel scales with the game's UI; on very small screens or with a large UI scale it can clip at the bottom. Lower the UI scale in GD settings, or rotate to landscape. Landscape is the supported orientation for generation.

Publishing

Making the download buttons work

The download page doesn't hardcode anything — it reads releases.js. A button works when three things line up: the repo in GENESIS_REPO, the tag on the release, and the exact asset filename in that release.

1. Asset naming

Build each platform, then upload with these names (they're what releases.js expects):

PlatformAsset filenameBuild target
Windowsgenesis-windows-x64.geodeWin64
macOSgenesis-macos-universal.geodeMacOS (arm64 + x86_64)
Android 64genesis-android64.geodeAndroid64
Android 32genesis-android32.geodeAndroid32
iOSgenesis-ios.geodeiOS

2. Create the release

terminal
gh release create v1.0.0 \
  build-win/genesis-windows-x64.geode \
  build-mac/genesis-macos-universal.geode \
  build-android64/genesis-android64.geode \
  build-android32/genesis-android32.geode \
  build-ios/genesis-ios.geode \
  --title "GENESIS v1.0.0" \
  --notes-file CHANGELOG.md

That produces URLs the site already knows how to build:

assets
https://github.com/BeginnerCoder142011/Genesis/releases/download/v1.0.0/genesis-windows-x64.geode
https://github.com/BeginnerCoder142011/Genesis/releases/download/v1.0.0/genesis-android64.geode

3. Point the site at your repo

releases.js
const GENESIS_REPO = {
  owner: 'BeginnerCoder142011',
  repo: 'Genesis'
};

const GENESIS_RELEASES = [
  {
    version: '1.1.0',
    tag: 'v1.1.0',
    date: '2026-12-01',
    channel: 'stable',
    geode: '5.0.0',
    gd: '2.2081',
    latest: true,
    assets: {
      windows: { file: 'genesis-windows-x64.geode', size: '1.2 MB', arch: 'Win64 · x64' },
      /* macos, android, android32, ios ... */
    },
    changes: [ { k: '+', text: 'What changed.' } ]
  }
];

Newest release first. The latest: true flag drives the changelog badge, the hero version pill and the big download card; every entry in the array becomes a row in the version history table.

Two safety switches. If GENESIS_REPO.owner is still yourname, every button refuses to navigate and shows a configuration warning — that's how a fresh copy of the site avoids shipping 404 links. And while a release has pending: true, its buttons open the GitHub releases page instead of a missing asset. This site is already pointed at BeginnerCoder142011/Genesis, so only the pending flag applies.

Unlisted beta builds

A prerelease goes in GENESIS_BETA rather than the stable array, flagged unlisted: true so it stays out of the changelog and version history. Access is link-only: the Stable/Beta toggle is injected only when the download page is opened with ?channel=beta, and every other visit forces the stable channel. Testers are pointed at beta.html, which carries the loader install steps, the test checklist and the report template. Its assets use version-prefixed names (genesis-1.1.0-beta.1-windows-x64.geode) and are published with --prerelease.

4. Host the site on GitHub Pages

The site is plain static files — no build step. Push index.html, download.html, docs.html, styles.css, releases.js, preview.js, .nojekyll and .github/workflows/pages.yml to main, then:

  1. Repo → Settings → Pages.
  2. Set Source to GitHub Actions.
  3. Push again (or run the workflow manually). It publishes on every commit to main.

Live URL: https://beginnercoder142011.github.io/Genesis/

5. Automate the build (optional)

With the Geode GitHub Action you can build every platform in CI and combine them into one archive:

.github/workflows/build.yml
- uses: geode-sdk/build-geode-mod@main
  with:
    sdk: 'latest'
    target: ${{ matrix.target }}      # Win64 / MacOS / Android32 / Android64
    combine: true

Then attach the combined .geode to a release, or build per-platform and upload all five assets.
